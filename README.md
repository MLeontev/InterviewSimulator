# InterviewSimulator

InterviewSimulator - это онлайн-платформа для симуляции технических собеседований разработчиков. 
Платформа позволяет кандидатам проходить пробные собеседования для проверки теоретических знаний и навыков написания кода и получать обратную связь с оценками и рекомендациями по дальнейшей подготовке.

---

## Возможности платформы

*   **Выбор пресетов:** Собеседования по различным технологическим стекам и уровням сложности (грейдам).
*   **Два типа заданий:** Теоретические вопросы со свободным текстовым ответом и практические задачи на программирование.
*   **Редактор кода:** Написание и запуск кода решений непосредственно в браузере.
*   **Тестирование решений:** Автоматическая проверка кода на тест-кейсах с замером времени выполнения, потребления памяти и выводом ошибок.
*   **Итоговый отчет:** Формирование оценок по компетенциям, разбор сильных и слабых сторон, рекомендации по дальнейшему обучению.
*   **Ограничение по времени:** Общий таймер на сессию с автоматическим сохранением ответов и завершением интервью при истечении лимита.

---

## Процесс прохождения интервью

1.  **Выбор пресета:** Пользователь запускает сессию собеседования, выбирая пресет под свой технологический стек и грейд. Далее система подбирает набор заданий.
2.  **Выполнение заданий:** Кандидат последовательно выполняет задания в течение ограниченного времени:
    *   **Теоретические вопросы:** Пишет развернутые ответы.
    *   **Алгоритмические задачи:** Пишет код во встроенном редакторе.
3.  **Автопроверка кода:** При отправке кода решение автоматически прогоняется через тест-кейсы. После проверки кандидат получает вердикт.
4.  **Завершение сессии:** Сессия завершается при выполнении всех заданий, вручную кандидатом или автоматически по истечении таймера.
5.  **Генерация итогового отчета:** После завершения интервью формируется структурированный отчет:
    *   Общий балл и вердикт по собеседованию.
    *   Разбор каждого ответа с оценкой и фидбеком.
    *   Список сильных и слабых сторон, а также рекомендации по подготовке.

## Технологический стек

*   **Бэкенд:** .NET 10, C#, ASP.NET Core, Entity Framework Core, MediatR, MassTransit, Docker.DotNet.Enhanced

## Локальный запуск

Для запуска всей инфраструктуры проекта (бэкенд, фронтенд, база данных и сервер авторизации Keycloak) используется Docker Compose.

### Предварительные требования
*   Установленный Docker и Docker Compose.
*   Кредиты (Client ID и Client Secret) для доступа к **GigaChat API**.

### Шаги для запуска

1.  **Настройка переменных окружения:**
    Создайте файл конфигурации `.env.local` в директории `infra/env/` на основе примера:
    ```bash
    cp infra/env/.env.local.example infra/env/.env.local
    ```
    Откройте созданный файл `infra/env/.env.local` и укажите ваши настройки:
    *   `GIGACHAT_CLIENT_ID` и `GIGACHAT_CLIENT_SECRET` — ключи доступа к GigaChat.
    *   `HOST_CODE_EXECUTION_ROOT` — абсолютный путь к папке `backend/.code-exec-tmp` на вашей локальной машине (например, `/Users/lmax/RiderProjects/InterviewSimulator/backend/.code-exec-tmp`).
    *   `REGISTRATION_EXTERNAL_URL` — внешний адрес страницы регистрации Keycloak (по умолчанию `http://localhost:3000/register`).

2.  **Запуск контейнеров:**
    Запустите сборку и старт сервисов из корневой директории проекта:
    ```bash
    docker compose -f infra/docker/compose.yml -f infra/docker/compose.local.yml --env-file infra/env/.env.local up -d --build
    ```

3.  **Доступ к сервисам:**
    После успешного старта всех контейнеров приложения будут доступны по следующим адресам:
    *   **Фронтенд (React App):** `http://localhost:3000`
    *   **Бэкенд Web API (Swagger):** `http://localhost:8090/swagger`
    *   **Панель администрирования Keycloak:** `http://localhost:8082` (логин/пароль по умолчанию: `admin` / `admin`)

## Тестирование

Тесты можно запустить как через IDE (VS, Rider), а также через консоль.

### 1. Юнит-тесты домена
```bash
dotnet test backend/tests/Interview.Domain.Tests
dotnet test backend/tests/CodeExecution.Domain.Tests
```

### 2. Интеграционные тесты
```bash
dotnet test backend/tests/Backend.IntegrationTests --filter "Category!=Docker"
```

### 3. Тесты Docker-песочницы
```bash
dotnet test backend/tests/Backend.IntegrationTests --filter "Category=Docker"
```
